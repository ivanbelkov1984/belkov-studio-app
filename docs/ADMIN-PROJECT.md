# Пульт студии (админка владельца) — проект

Статус: предложение от 06.11.2026, не начато. Решение о запуске принимает владелец.

## Нужна ли
Сейчас нет: заявок нет, приложение статичное и ничего не хранит, заявки приходят в личный Telegram.
Нужна с первых регулярных заявок (ориентир: от 3–5 в неделю или когда появится первый клиент на договоре). До этого её поддержка стоит дороже, чем экономит.

Важно: как только пульт начнёт хранить заявки на сервере, это обработка персональных данных на нашей стороне. Перед запуском подать уведомление РКН (черновик уже сохранён) и включить журнал согласий.

## Принципы
- Пульт — мини-приложение внутри бота студии в MAX (и Telegram), открывается только у владельца. Вход по подписанным данным запуска MAX/Telegram (HMAC, сверка с ID владельца), как у музыки. Работает с iPhone и iPad без отдельного логина.
- Данные только на сервере в РФ (PostgreSQL на VDS), копии в S3 FirstVDS.
- Контент-план остаётся в Notion, учёт задач — в ТЕКУЩАЯ_ЗАДАЧА.md и Drive. Пульт их не дублирует: он работает с заявками и публикацией.

## Функции MVP (по пользе)
1. **Заявки в одном месте.** Заявки из мини-приложения, бота Telegram и бота MAX попадают в один список: имя, контакт, что нужно, бюджет, источник (`src_channel`, `src_max`, ...), согласие на ПДн (дата и версия текста). Статусы: новая → в работе → предложение → договор → закрыта / отказ. Ответ клиенту прямо из пульта в его мессенджер. Пуш владельцу о новой заявке.
2. **Публикация в два канала сразу.** Текст + фото + кнопка «Открыть студию» уходят одновременно в канал Telegram и канал MAX, сразу или в назначенное время. Нет ручного копирования.
3. **Воронка по источникам.** Сколько открыли приложение → посчитали в калькуляторе → оставили заявку, по каждой метке источника и по неделям. Видно, какой пост или площадка приносит клиентов.
4. **Договор и акт из заявки.** Шаблоны уже есть (`app/docs/*.docx`): реквизиты клиента подставляются из заявки, на выходе готовый DOCX для отправки. После оплаты напоминание пробить чек в «Мой налог».
5. **Сроки хранения ПДн.** Автоудаление заявок без договора через 1 год, кнопка «удалить по запросу клиента», журнал удалений (требования политики и 152-ФЗ выполняются сами).

## Что не входит (сознательно)
Полная CRM, приём оплаты, рассылки (нужно отдельное согласие на рекламу), аналитика внутри мессенджеров, управление музыкой (у музыки своя админка).

## Технически
- Бэкенд: небольшой сервис на сервере (Python aiohttp или Node), порт 127.0.0.1:3001, nginx `studio.aiservicesint.ru/api/` уже проксирует туда.
- БД: отдельная база `studio` в существующем PostgreSQL, отдельная роль.
- Боты: вебхуки ботов студии Telegram и MAX на сервер (сейчас заявки идут в личку).
- Секреты (токены ботов) — в `/srv/studio/secrets/.env`, вносит владелец.

## Оценка
- MVP (функции 1–3): 2–3 рабочих сессии. 4–5: ещё 1–2.
- Расходы: 0 ₽ сверху (сервер и S3 уже оплачены).

## Порядок запуска
1. Решение владельца «делаем пульт».
2. Уведомление РКН (из черновика) — до приёма первой заявки на сервер.
3. MVP 1–3, проверка на тестовых заявках, затем 4–5.
