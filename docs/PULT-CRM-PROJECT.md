# Пульт студии как мини-CRM: проект

Статус: **P0 реализован и развёрнут 06.11.2026** (см. ниже «Что уже сделано в P0»); P1 и P2 — по очереди. Проект от 06.11.2026 на основе исследования ([REPORT-chatlabs-analogi-crm.md](research/REPORT-chatlabs-analogi-crm.md), пять заметок рядом). Уже работает: заявки, статусы, ответ клиенту (MAX), счета ЮKassa, публикация в два канала, воронка (см. [ADMIN-PROJECT.md](ADMIN-PROJECT.md)). Здесь — что добавить и в каком порядке.

## Принципы
1. Один владелец, телефон, MAX/Telegram. Каждый экран — до трёх нажатий; ввод минимальный (быстрые кнопки вместо печати).
2. У каждой заявки всегда есть «следующее действие + дата». Без этого заявка висит красной карточкой на экране «Сегодня».
3. У каждой заявки есть источник (код из ссылки), первый источник не затирается.
4. Весь контент приложения живёт в базе под версиями: правка → предпросмотр → публикация → откат одной кнопкой. Приложение всегда имеет вшитую копию на случай недоступности сервера.
5. Данные только на сервере в РФ, согласия и удаления журналируются. Рассылки только по согласию.
6. Метрики показываем числами и возрастом («7 из 23», «3 дня без ответа»), проценты только когда данных достаточно.

## Как пульт управляет логикой приложения

Приложение при запуске читает `GET /api/config` (кэш ETag, запасная копия `defaults.json` внутри приложения). Конфиг собирается из опубликованных блоков:

| Блок конфига | Что меняет в приложении | Пример |
|---|---|---|
| `services`, `packages`, `pricing` | карточки услуг, цены «от», калькулятор (коэффициенты, шаги) | поднять цену, добавить пакет, скрыть услугу |
| `faq`, `cases`, `texts` | тексты экранов, ответы на вопросы, кейсы | заменить заголовок главного экрана |
| `banners` | баннер на главной с датой «с–по» и кнопкой | «Ноябрь: бриф бесплатно» |
| `promos` | промокод в форме заявки; сервер проверяет код и фиксирует скидку | `START10` на 10% до 30.11 |
| `sources` | текст и баннер по коду из ссылки (`src_channel`, `src_max_post12`) | своё приветствие для гостей из канала |
| `mode` | приём заявок открыт/закрыт, режим обслуживания, рабочие часы, фраза о сроках ответа | «ответим завтра с 10:00» вне часов |
| `flags` | включить/выключить функцию для площадки, источника или доли пользователей | показать калькулятор только из MAX |

Защита: схема-валидация на сервере (цена ≥ 0, ссылки только `https:`, `tg:`, `max:`), вывод через `textContent`, запись только владельцем по подписанным данным запуска, журнал изменений, откат одним нажатием (старая версия копируется заново, история не стирается).

## Данные (добавляется к текущей схеме)
`content_blocks` (ключ, значение JSON), `content_versions` (блок, версия, автор, время, значение), `content_pointers` (блок → опубликованная версия), `sources` (код, название, приветствие), `promos` (код, процент или сумма, период, лимит), `promo_redemptions`, `consents` (вид pd/ads, версия текста, дата, отзыв), `message_templates`, `tasks` (привязка, срок, выполнено), `notes`. В `leads`: `next_action`, `next_action_at`, `lost_reason`, `first_response_at`, `tags`. Платежи: `receipt_done` уже есть, добавить `receipt_due_at`.

## Порядок работ (оценка из исследования; фактическая зависит от согласований)
- **P0, 3–4 сессии:** `/api/config` и вшитая копия; редактор контента с версиями, предпросмотром и откатом; режим (приём закрыт, рабочие часы, фраза); экран «Сегодня»; поля «следующее действие» и причина потери; справочник источников и тексты по `src_*`.
- **P1, 4–5 сессий:** промокоды и акции; карточка клиента с заметками, тегами, задачами; быстрые ответы и автоответ вне часов; согласия и журнал; индикатор лимита НПД и напоминание про чек; экспорт CSV; фичефлаги.
- **P2, 5–7 сессий (только при трафике и после согласий):** рассылки по сегментам с предпросмотром «себе» и отпиской; автодожим внутри диалога; реакция на комментарии MAX; шаблоны постов с источником; A/B только по клику на кнопку.

Не делаем: полноценный конструктор сценариев, роли для команды, внешнюю CMS, ИИ-ответы клиентам без проверки владельцем.

## Что отличит студию от ChatLabs (из исследования)
Калькулятор и демо в самом мини-приложении (у ChatLabs их нет), прозрачная смета «модуль × цена» вместо расплывчатого «от», FAQ про предоплату, гарантию и права на код, оферта и договор. Пульт показывает это как живое доказательство: клиент видит ровно то, чем студия управляет.

## Что уже сделано в P0 (06.11.2026)
- **Конфиг приложения:** `GET /api/config` (ETag, кэш 30 с), блоки `mode`, `banner`, `prices`, `calc`, `sources`, `faq`; приложение применяет их поверх вшитых данных, при недоступности сервера берёт последнюю копию из браузера или вшитые данные.
- **Версии и откат:** каждая публикация — новая версия (`content_versions`), указатель `content_pointers`; откат создаёт новую версию со старым содержимым, история не стирается; журнал в `audit`.
- **Проверка на сервере:** границы цен, формат часов и дат, ссылки только `https://`, `tg://`, `max://`, `#/`, длины текстов, белый список блоков; вывод в приложении через `textContent`.
- **Экран «Сегодня»:** новые без ответа, действия с просроченным сроком, предложения без движения 3+ дня, заявки без следующего действия, неоплаченные счета, чеки «Мой налог» не пробиты, индикатор лимита НПД (70/85/95%).
- **Заявка:** следующее действие и срок (быстрые «Завтра / 3 дня / неделя»), причина отказа (обязательна для «Отказ»), теги, отметка «я уже ответил(а)», время первого ответа.
- **Экран «Контент»:** режим работы (закрыть приём, рабочие часы, текст вне часов), баннер с датами, цены и скрытие услуг, калькулятор, источники (приветствие по ссылке), FAQ, история версий и откат.
- **Проверено:** серверные сквозные тесты (в том числе отказ без подписи, неверные данные, откат) и в настоящем браузере на изолированном стенде: пульт, формы, публикация, затем вид клиента (баннер, приветствие по источнику, сообщение вне часов, смена цены, скрытая услуга, FAQ). Тестовые данные удалены, боевой конфиг возвращён в нейтральное состояние.
- **Источники и ссылки:** код источника без префикса: строка `channel | Канал | Привет!` работает для ссылки `…?startapp=src_channel`.
