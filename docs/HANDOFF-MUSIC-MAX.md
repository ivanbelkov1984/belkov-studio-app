## 3. MAX: как устроено и что я прошёл (практика)

### Платформа и лимиты
- business.max.ru: профиль самозанятого Ивана (организация `se14910384`). Верификация через Госуслуги, её делает только сам владелец.
- Лимиты самозанятого (dev.max.ru, проверено 05.11): **2 бота** (оба заняты), **1 публичный канал через платформу** (занят студией). Ник бота присваивается автоматически: `se<orgid>_bot`, `se<orgid>_1_bot`. Цифровой ID и Госключ самозанятому недоступны.
- Через профиль можно подать заявку в партнёрскую программу («Стать партнёром», категория «Заказная разработка»). Это задача студии, не музыки.
- Передача бота другому владельцу в MAX не подтверждена.

### Бизнес-канал и обычный канал
- **Бизнес-канал** создаётся через бота «Каналы в MAX для бизнеса» из профиля организации. Принадлежит организации, даёт бизнес-инструменты и расходует лимит.
- **Обычный канал** (`channel_…`) создаётся в приложении из личного аккаунта (через Цифровой ID). Лимит платформы он не расходует.
- Каналы между собой не связаны: подписчики, посты и статистика у каждого свои.

### Настройка бота на business.max.ru
Раздел «Чат-боты» → бот:
- имя, описание, аватар;
- раздел мини-приложения: URL (https), кнопка «Открыть»;
- публикация.

Известные грабли:
- **При наборе на business.max.ru теряются символы.** Вводить через form_input (заполнение поля целиком) и после этого читать значение через JS. Если хвост искажён, стереть его Backspace и проверить снова.
- **Загрузка файла (аватар) из Chrome-инструмента заблокирована.** Аватар загружает сам владелец, ему нужно дать путь к файлу.
- Изменения бота могут идти через модерацию. Проверять статус «Опубликован».

### Мини-приложение в MAX
- Подключить оба SDK: `https://telegram.org/js/telegram-web-app.js` и `https://st.max.ru/js/max-web-app.js`. Определять платформу: `window.Telegram.WebApp.initData` → Telegram, `window.WebApp` → MAX, иначе веб.
- Главная кнопка: в Telegram MainButton, в MAX своя кнопка в интерфейсе (док внизу экрана). BackButton есть в обоих.
- Хранилище: Telegram CloudStorage, MAX DeviceStorage, веб localStorage.
- Поделиться: MAX `shareMaxContent`, Telegram ссылка `t.me/share/url`.
- Параметр запуска: `?startapp=` (в TG `t.me/<bot>?startapp=…`, в MAX `max.ru/<bot>?startapp=…`). Удобно размечать источник, например `src_channel`, `src_max`, `src_qr`. Части параметра соединять через `__`.
- Ссылки наружу открывать через openLink платформы, а не через `<a target=_blank>`.

### Папки в web.max.ru
Настройки → Папки → «Создать папку» → название → отметить чаты. Клик по строке через ref может не отметить пункт, надёжнее `input[type=checkbox].click()` по строке с нужным названием. Список виртуализирован, его нужно прокручивать.

## 4. Telegram: что делал для студии (для паритета)

- **BotFather**:
  - /setdescription, /setabouttext, /setuserpic;
  - кнопка меню (Menu Button → Web App, текст «Открыть»);
  - Main App включён;
  - Direct Link `t.me/<bot>/<name>` требует обложку 640×360.

- Диалоги Telegram Desktop иногда закрываются. В диалоге выбора файла вводить полный путь.

## 6. Правила работы (ограничения среды, хуки)

- Язык общения — русский. Ответ владельцу: «сделано / подтверждение / препятствие / следующий шаг», не больше 4 строк, если он не просит подробностей.
- Базовый checkout только для чтения. Изменения делать только в worktree.
- Прямой push в main/MAIN запрещён. Force push заблокирован хуком.
- Публикация на GitHub Pages из подпапки: `git subtree split --prefix <dir> -b gh-pages` и обычный `git push origin gh-pages`. Split детерминирован, поэтому push проходит без force.
- После публикации проверить, что сайт открывается, через `until curl … | grep -q <маркер>; do sleep 5; done`. Простой `sleep` заблокирован.
- Статус любой интеграции описывать четырьмя ступенями: установлено → выполнен вход → доступно Claude → проверено действием.
- Вход, верификацию, загрузку файлов и смену токенов делает владелец. Ему нужно дать один точный шаг.
- Не подписывать новые сервисы и не включать платные функции.
